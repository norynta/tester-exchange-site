From Replit to Google Play

Replit projects can be web apps or Expo (React Native) mobile apps. A web app is wrapped with Capacitor; an Expo app is built into an .aab with EAS Build. Look at the project files to see which one you have.

What Replit gives you is a web app or an Expo mobile project. Google Play only takes a signed Android App Bundle (.aab), so the work is getting from one to the other. Features and export options of any builder change often, so check Replit's current documentation for your plan.

Wrap the web app with Capacitor

Capacitor is an open-source runtime that loads your built web files inside an Android app. The AI prompt below asks your builder (or any coding assistant) to set it up.

  1. Get the project code out of Replit (GitHub sync or download) and open it on your computer. Install Node.js and Android Studio.
  2. Choose an application ID like com.yourname.yourapp. It must be unique and it can never be changed after you upload to Google Play.
  3. Run npx cap add android once, then npx cap sync android after every web build.
  4. Open the Android project (npx cap open android) and create a signing key in Android Studio: Build, Generate Signed Bundle / APK, Android App Bundle. Keep the key file and passwords safe; you need them for every update.
  5. Test the .aab on a real phone before you upload it.

Give the app something a plain website does not: working offline pages, native share, notifications or at least a good mobile layout and a real purpose. Google can reject apps that only repackage a website without added value.

Run the closed test: 12 testers for 14 days

Google requires personal developer accounts created after 13 November 2023 to run a closed test with at least 12 testers who stay opted in for 14 days in a row before they can apply for production access. The requirement is the same whatever tool built Replit app.

  1. In Play Console, create the app (name, default language, app or game, free or paid) and fill in the declarations Google asks for.
  2. Open Test and release, then Testing, then Closed testing. Create a release and upload your signed .aab file.
  3. Under Testers, add an email list or a Google Group. If you use Tester Exchange, the group to add is testerexchange-testers@googlegroups.com and we add our testers to it.
  4. Check Countries / regions includes the countries your testers live in.
  5. Send the release for review. When the app status is Published, share the opt-in link; each tester must open it and accept.
  6. Keep at least 12 testers opted in for 14 consecutive days. Aim for 15 so one dropout does not move your date.
  7. When the Dashboard shows the Apply for production button, apply and answer the three parts of the form.

Common mistakes

  • Do not use the Play Console "internal testing" track for the 12-tester requirement. It has to be a closed (or equivalent) test with 12 testers opted in.
  • Do not change the application ID after the first upload. A new ID is a new app and restarts the 14 days.
  • Do not hand testers a debug build or an .apk. Upload a signed .aab to the track so testers install from Google Play.
  • Make sure the app does real work on first launch. Testers who see a blank page or login wall they cannot pass will not keep using it.
  • Plan for 15 testers, not 12: dropouts before day 14 push the date back.

Frequently asked questions

Can I publish a Replit app on Google Play?

Yes, once you have a signed Android App Bundle (.aab). Replit projects can be web apps or Expo (React Native) mobile apps. A web app is wrapped with Capacitor; an Expo app is built into an .aab with EAS Build. Look at the project files to see which one you have.

Does Replit get me the 12 testers?

No. The 12 testers are a Google Play requirement for new personal developer accounts, so you recruit them yourself or use a service. Tester Exchange provides real people on their own phones, or you can swap tests for free.

Do I need a new Play Console account for an AI-built app?

No. Google Play does not care which tool wrote the code. What matters is the account type: personal accounts created after 13 November 2023 need the 12-tester, 14-day closed test; organization accounts are not subject to that requirement.

Can the testers be the same for several apps?

Testers opt in per app. A person can test several of your apps, but each person has to opt in to each app separately.
